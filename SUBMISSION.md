## Notes for the reviewer

- **Running locally**:
  - Start the backend: `python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000`
  - Start the frontend: `python -m streamlit run frontend/app.py --server.port 8501`
  - Run test suite: `python -m pytest backend/tests/ -v`
  - Seed demo data: `python -m backend.app.seed`
- Both FastAPI Swagger docs (`http://127.0.0.1:8000/docs`) and the Streamlit interface (`http://127.0.0.1:8501`) run simultaneously.

## Stack

| Layer | What you used | Why |
|-------|---------------|-----|
| Frontend | Streamlit + Custom CSS | High developer velocity, clean responsive components, and seamless Python integration. |
| Backend | FastAPI + Pydantic v2 | High performance async ASGI framework, automatic OpenAPI documentation, and strict request/response data validation. |
| Database | PostgreSQL / SQLite | Relational integrity with foreign keys, indexes, and unique constraints. SQLite for zero-setup local dev; PostgreSQL ready for cloud deployment. |
| ORM | SQLAlchemy 2.0 | Explicit query compilation, session lifecycle management, and relationship loading. |
| Migrations | Alembic | Tracked, repeatable, and autogenerated schema versioning. |
| Authentication | Bcrypt + PyJWT | Industry standard salted password hashing and stateless token-based authorization. |

## Goal checklist

| # | Goal | Status | Notes |
|---|------|--------|-------|
| 1 | Accounts and roles | Done | Enforced on server via `require_role(PROPERTY_MANAGER)`. Contractors receive HTTP 403 on manager endpoints and cannot see rent data. |
| 2 | Units | Done | Unit number, address, monthly rent, tenant name. Soft-delete archive and restore. 5-day grace period. |
| 3 | Maintenance requests | Done | M:N contractor assignments. Can be created by manager or contractor. Description and priority editable by both; assignment restricted to manager. |
| 4 | Maintenance request lifecycle with rules | Done | State machine: `REPORTED -> TRIAGED -> SCHEDULED -> RESOLVED -> TRIAGED`. Cannot move to `SCHEDULED` without an assigned contractor. Reopen returns to `TRIAGED`. Illegal transitions rejected with descriptive HTTP 400. |
| 5 | Assignment | Done | M:N relationship. Only Property Manager can assign/unassign. Contractors only see tickets assigned to them across units. |
| 6 | Finding requests | Done | Server-side text search on descriptions & units, filtering by status, priority, unit, and contractor, sorting, and pagination. |
| 7 | Acting on rent for many units at once | Done | `POST /api/rent/bulk` classifies rows into matched, underpaid, overpaid, and unmatched. One-click CSV rent roll download via `GET /api/rent/roll/csv`. |
| 8 | A dashboard | Done | Headline KPIs (active/archived units, collected rent, overdue units, open/scheduled/resolved requests), status breakdown, contractor workload, 8-week resolution trend chart, and unattended tickets (>14 days). |
| 9 | History you cannot rewrite | Done | Append-only `maintenance_timeline_events` recording creation, status changes with old/new values, contractor assignments/unassignments, and notes. No edit or delete endpoints exist. |
| 10 | Rent alerts | Done | Overdue units past the 5-day grace period appear in alerts area with an active count badge in the sidebar navigation. Dismissing is scoped per unit and month; if unpaid in subsequent months, the alert returns automatically. |

## What are you least happy with in this codebase, and why?

In `rent_service.get_portfolio_rent_roll`, we calculate monthly balances dynamically in Python by querying payments for each active unit. While this is fast and clean for dozens or hundreds of units, at 10,000+ units, it would be much more performant to compute this via a single SQL query using `GROUP BY` and a window function or maintain a pre-aggregated monthly balance summary table.
